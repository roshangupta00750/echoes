## 1. Executive Summary

This log records how ECHOES was built, in 35 prompts. ECHOES is a single-screen neon arcade game for phones and tablets, made with Godot 4.7.2 (GL Compatibility renderer) and GDScript. Everything on screen is drawn in code at a 384×216 base resolution: there are no sprite sheets, no third-party plugins and no runtime downloads. The music and sound effects are WAV files generated by a script in the repository (`tools/make_audio.py`), not recorded or licensed samples.

The work moved through seven phases: the core game and its arcade feel; difficulty modes and controls; LAN multiplayer with zombie infection; fairness and readability; reasons to come back and sharing; release and open-source packaging; and finally iPhone and iPad support. Each prompt below is the instruction for one step, followed by what was built for it.

## 2. Phase I: Core Game and Arcade Feel (Prompts 01–08)

### Prompt 01: Project Scope and Constraints

```
Make a retro neon arcade game called ECHOES for Android phones held in landscape, in Godot 4 with the GL Compatibility renderer. Draw everything in code at 384x216 and scale it up with sharp pixels, so it looks the same on every phone. Keep the code in a few small scripts: one for the rules and drawing, one for menus and flow, one for networking.
```

**Technical Implementation:**
- **Viewport:** 384×216 base size, stretch mode `viewport`, aspect `expand`, nearest-neighbour filtering.
- **Scripts:** `scripts/game.gd` (rules, echoes, drawing), `scripts/main.gd` (menus, HUD, saves, controls), `scripts/net.gd` (LAN), plus `scripts/art.gd` and `scripts/sound.gd`.
- **Rendering:** custom `_draw()` on `Node2D` layers; no textures except the two pixel fonts and the app icon.

### Prompt 02: Arena, Player Movement and Shards

```
Put a single arena in the middle of the screen. The player is a glowing dot that moves at about 92 pixels a second with smooth acceleration. Each level has five gold shards, one at a time, and touching the shard's glow ring counts, not just the diamond. Collect all five before the timer runs out to clear the level.
```

**Technical Implementation:**
- **Arena:** `ARENA := Rect2(-165, -78, 330, 156)`, centred on the screen.
- **Movement:** `SPEED := 92.0`, player radius `P_R := 3.5`, clamped inside the arena.
- **Pickup:** `PICK_R := 14.0` (the glow ring), `SHARDS := 5` per level, `LEVEL_TIME := 15.0` seconds.

### Prompt 03: Recording Runs and Echo Replay

```
Record the player's position every physics frame. When a level is cleared, that recording becomes an echo: a hollow ghost that replays the same path from the start of every following level, rests at its starting point for a moment, then loops forever. Touching a moving echo ends the run. Echoes are harmless while they rest.
```

**Technical Implementation:**
- **Recording:** each player's `rec` is a `PackedVector2Array` filled at 60 Hz; `_add_run()` stores it in `runs` when the level clears.
- **Replay:** `ghost_pos(i, t)` gives an echo's position at level time `t`; `ghost_live()` is false while it rests, so a resting echo can't catch you.
- **Limit:** `max_echoes()` keeps every echo in solo play, and the newest 24 in a crowded LAN match.

### Prompt 04: Close Calls and Scoring

```
Reward brave play. If the player slips past an echo, coming within about 13 pixels and then leaving again, count a close call. Score 100 times the level for a shard, 25 times the level for a close call, and a time bonus for clearing quickly.
```

**Technical Implementation:**
- **Close call:** `near_in` tracks "player:echo" pairs inside 13 px; the bonus is paid when the pair separates, so hovering behind an echo pays nothing.
- **Score:** `100 * level` per shard, `25 * level` per close call, time bonus `(lvl_time() - lt) * 20 * level` on a clear.
- **Breakdown:** `sc_shards`, `sc_close` and `sc_bonus` are kept separately for the results screen.

### Prompt 05: Level Flow and Feel

```
Start each level with a 3-2-1 countdown and GO. When a shard is taken, show a ring and particles and freeze the game for a split second. When the player is caught, shake the screen, flash, vibrate and stop for a moment. Restarting takes one tap. The first tips explain the idea: that ghost is you, from level 1, so keep your path tidy.
```

**Technical Implementation:**
- **States:** `state` runs `ready` → `play` → `clear` or `dead` (solo) / `over` (multiplayer).
- **Hit-stop:** `hit_stop = 0.045` on a pickup and `0.12` on a death, with `shake`, `flash` and `Input.vibrate_handheld()`.
- **Tips:** `TIPS` in `main.gd`, shown under the arena where nothing else is drawn.

### Prompt 06: Neon Look and CRT Shader

```
Neon on near-black: a faint purple grid and a magenta arena border. The player is white-hot with a cyan ring and a comet trail. Echoes are hollow rings in their own colours and shards are gold. Add a light CRT effect with scanlines, slight colour fringing, a soft glow and a vignette, and a setting to turn it off.
```

**Technical Implementation:**
- **Shader:** `shaders/crt.gdshader` on a full-screen `ColorRect` (aberration 0.0005, glow threshold 0.4, scanlines 0.9, vignette 0.4).
- **Colours:** echo hues in `HUES`, gold `GOLD`; no echo or player colour is cyan or gold, so the player and shards always stand out.
- **Fonts:** a 6×8 and a 12×16 pixel font in `assets/art`, drawn by `Art.text()`.

### Prompt 07: Soundtrack and Sound Effects

```
Make synthwave chiptune music for the title screen, for play, and a more intense track for later levels, plus sound effects: shard pickups that rise in pitch, a close-call whoosh, a death sting and a level-clear chime. Generate them with a script in the repository so there are no outside sound files.
```

**Technical Implementation:**
- **Generator:** `tools/make_audio.py` renders 16-bit mono WAVs at 32 kHz into `assets/audio/`, with exact loop points for the music.
- **Pickups:** `sfx_shard1.wav` to `sfx_shard5.wav`, one step higher for each shard in a level.
- **Playback:** `scripts/sound.gd` (`play_music()`, `sfx()` with a minimum gap between repeats).

### Prompt 08: Menus, Results and Test Bots

```
Add a title screen with the game playing itself behind it, a results screen with the score, the level and what caught you, a settings screen and a pause. The Android Back button should step back through the screens instead of quitting. Add a bot and a screenshot option so the game can be tested without a person.
```

**Technical Implementation:**
- **Demo:** `start_demo()` runs a bot game behind the title, with effects drawn faintly.
- **Back button:** `config/quit_on_go_back=false` and `_back()` in `main.gd`.
- **Test flags:** `--autoplay`, `--mode=`, `--shot=PATH --shot_at=SECONDS --quit_after_shot`, `--screen=NAME`.

## 3. Phase II: Difficulty and Controls (Prompts 09–13)

### Prompt 09: Three Modes and Echo Tuning

```
Add three modes: Normal (the default), Hard and Extreme. There is no Easy mode: the first five levels of Normal are gentle enough for anyone. Harder modes give less time, a shorter head start, shorter rests and faster echoes. In every mode echoes speed up a little from level 8.
```

**Technical Implementation:**
- **Level time:** `lvl_time()`: Normal 15 s (14 s from level 11), Hard 14 s, Extreme 13 s.
- **Echo timing:** `g_delay()` 1.0 / 0.8 / 0.8 s head start; `g_rest()` 60 / 40 / 30 frames of rest between loops.
- **Echo speed and size:** `g_speed()` 1.0 / 1.15 / 1.25×, plus 3% per level from level 8; `g_r()` 3.5 px, 4.5 px on Extreme.

### Prompt 10: Extreme Mode: Hunter Echo and Drifting Shards

```
In Extreme, the newest echo hunts you: it still follows its own path but leans toward you. Give it spikes and a red pulse so it reads by shape, not only colour. Put most shards on old echo paths, and make a shard that nobody takes for a few seconds start to drift.
```

**Technical Implementation:**
- **Hunter:** `is_hunter()` marks the latest level's echoes; `_leash_tick()` bends them up to `LEASH := 16.0` px toward the nearest player at `LEASH_SPEED := 30.0` px/s.
- **Shards on paths:** `_path_point()` picks a point on an older echo's path, avoiding its first 2 seconds.
- **Drift:** after `SHARD_STILL := 4.0` s a shard moves toward `shard_goal` at `SHARD_DRIFT := 22.0` px/s.

### Prompt 11: Mode Unlocks and Per-Mode Bests

```
Hard opens when you clear level 6 on Normal, and Extreme when you clear level 6 on Hard. Locked buttons show a padlock. Keep a best score and a best level for each mode.
```

**Technical Implementation:**
- **Unlock rule:** `UNLOCK_AT := 6`; `_unlock_after()` sets `unl_hard` / `unl_extreme` in the save.
- **Bests:** `best_<mode>` and `level_<mode>` keys, read by `best_of()` and `level_of()`.
- **Buttons:** `_mode_row()` draws open modes as options and closed ones in the `locked` button style.

### Prompt 12: Control Schemes

```
Offer three controls in Settings. Touch: a floating stick wherever the thumb lands. Tilt: steer by tilting the phone. Tilt plus touch: tilt steers, holding a finger anywhere is the accelerator, and lifting it stops. Add a tilt speed setting, invert X and Y, and a live dot to test tilt.
```

**Technical Implementation:**
- **Sensors:** `input_devices/sensors/enable_accelerometer` and `enable_gravity` turned on in `project.godot`.
- **Schemes:** `save["control"]` is `touch`, `tilt` or `tilt_hold`; `_movement()` turns each into a move vector.
- **Settings:** `sens` (low / medium / high), `flip_x`, `flip_y`, and the TILT TEST box in `_draw_settings()`.

### Prompt 13: Tilt Calibration

```
Sensor axes differ between phones, so add a three-step calibration: hold the phone still and tap, tip the right side down, then tip the far edge away. Save which way is right and which way is away, and use them so the dot follows the phone on any device. Open it on its own the first time a tilt control is picked.
```

**Technical Implementation:**
- **Steps:** `_go_calib()`, `_calib_tick()` and `_draw_calib()` wait for the phone to be held steady at each step.
- **Saved vectors:** `tilt_r` and `tilt_u` in the save; `_tilt()` projects gravity onto them.
- **First use:** `_pick_control()` opens calibration when there is no `tilt_r` yet.

## 4. Phase III: LAN Multiplayer and Zombies (Prompts 14–18)

### Prompt 14: LAN Discovery and Sessions

```
Add LAN play like the old Mini Militia: one phone hosts and friends on the same Wi-Fi or hotspot join. The host announces itself every second and joining phones list the games they find, with an address keypad as a fallback. The host runs the match and sends the state to everyone many times a second.
```

**Technical Implementation:**
- **Transport:** ENet on `PORT := 47010`, up to 8 players; discovery by UDP broadcast on `DISC_PORT := 47011` with the tag `MAGIC := "ECHOES1"`.
- **Android:** `set_broadcast_enabled(true)` on the listener, so Android takes its multicast lock and hears the host.
- **Snapshots:** the host sends `snapshot()` at 30 Hz; clients apply it with `apply_snapshot()`.

### Prompt 15: Fair Catches Over the Network

```
Nobody should be caught by lag. Each player judges their own catches and pickups on their own screen and reports them, and the host checks the report before accepting it. Everyone's runs become echoes for everyone. A player caught mid-level becomes an echo from the next level, never halfway along its path.
```

**Technical Implementation:**
- **Reports:** clients send `c_died`, `c_take` and `c_zcatch`; the host applies them with `remote_caught()` and `remote_take()`.
- **Checks:** a pickup counts only if the shard number matches and the player is near the shard in the host's view too.
- **Echo rule:** runs are added at the level change, so an echo always starts from the beginning of its path.

### Prompt 16: Names and Lobby

```
Players set a name in Settings. Tapping the name field brings up the phone keyboard, and the name is shown in the game's own pixel font. The host picks the mode in the lobby, and every mode is open in LAN games. On the results screen the winner is listed first.
```

**Technical Implementation:**
- **Name entry:** an invisible `LineEdit` takes the keyboard input; `_name_clean()` keeps A–Z, 0–9 and spaces, up to 10 characters.
- **Lobby:** `_draw_lobby()`, `_host_mode()`; `h_lobby()` keeps clients in sync with the host's choice.
- **Results:** `_mp_ranked()` orders players with the winner on top.

### Prompt 17: Zombie Infection

```
In LAN games a caught player isn't out. They come back as a zombie, still steered by that person: square, toxic yellow-green, with teeth. Zombies move a bit slower than people, pass through echoes and can't take shards. Touching a person turns them into a zombie. A new zombie blinks for a moment before it can catch anyone, and zombies lunge when they get close, so people in the open can still be caught. The last person standing wins.
```

**Technical Implementation:**
- **Zombie rules:** `ZOMBIE_SPEED := 0.9`, `ZOMBIE_GRACE := 1.5` s, `ZOMBIE_PTS := 300` × level per catch; colour `ZCOL`.
- **Lunge:** within `LUNGE_RANGE := 34.0` px, `LUNGE_SPEED := 1.75`× for `LUNGE_T := 0.35` s, every `LUNGE_CD := 3.0` s.
- **Spawning:** `spawn_pos()` starts zombies on the far side of the arena from the people.

### Prompt 18: No Hiding

```
Stop people from hiding. When the clock runs out, anyone who took no shard that level turns into a zombie, and they get a warning in the last five seconds. A phone that goes quiet, because it was locked or the app was put in the background, counts as caught.
```

**Technical Implementation:**
- **Warning:** "NO SHARD YET! TAKE ONE OR TURN" in the HUD for the last 5 s of a level.
- **Time-up rule:** in `_play()`, when the clock runs out, every person with `got == 0` is caught (and turns) before `_clear(true)`.
- **Silent phones:** `SILENT_OUT := 1.5` s without a position from a player and the host counts them as caught.

## 5. Phase IV: Fairness and Readability (Prompts 19–22)

### Prompt 19: Safe Spawns and Wait Rings

```
Every death should feel fair. Start each level at whichever of about 15 spots is furthest from where the echoes wait. Give each resting echo a ring that runs down until it moves, flashing just before it goes.
```

**Technical Implementation:**
- **Spawn:** `_pick_origin()` scores the 15 `SPAWNS` against each echo's first point and takes the best.
- **Wait rings:** `ghost_wait(i, t)` gives the time left before an echo moves; the ring is drawn from it.

### Prompt 20: Path Preview and Shard Safety

```
During the 3-2-1, dot the first second of every echo's path, and show the newest echo's whole path. Never place a shard where an echo is now or will be within the next second.
```

**Technical Implementation:**
- **Preview:** drawn in the `ready` state from `ghost_pos()` samples.
- **Shard placement:** `_new_shard()` tries up to 40 points and rejects any within 26 px of an echo now, in 0.5 s or in 1 s, or within 60 px of a player.

### Prompt 21: Death Replay and Results Breakdown

```
When you're caught, freeze for a second, ring the echo that got you, trace its whole path and label it with the level it came from. A time-up says how many shards you got. The results show the score first, then one headline, then the breakdown, then a tip. Resuming from pause gives a 3-2-1 first.
```

**Technical Implementation:**
- **Replay:** `REPLAY := 1.0` s; `killed_by` (which level's echo) and `killer` (which echo) drive the "YOUR LEVEL N SELF" label.
- **Results:** `_draw_over()` shows score, headline, `sc_shards + sc_close + sc_bonus`, and a tip.
- **Resume:** `hold_t` gives a countdown before the game moves again.

### Prompt 22: Shape Language and One UI Style

```
Give every object its own shape and size: the player is the biggest, solid and white-outlined, and the only thing with a trail; echoes are hollow rings; the hunter is spiked; zombies are square; shards are gold. Use one button style everywhere, with touch targets big enough for thumbs, menus on near-solid panels, and the interface drawn above the CRT so text stays sharp.
```

**Technical Implementation:**
- **Buttons:** `_btn()` with four kinds: `primary`, `selected`, `secondary`, `locked` (padlock); every button is at least 22 game pixels tall.
- **Colours:** selected options in `SEL` (cyan), labels in `LBL` (dim), values bright.
- **Layers:** the UI `CanvasLayer` is layer 30, above the CRT on layer 20.
- **HUD:** level, a score that pops gold when it rises, echo count, shard pips, a 5 px timer bar that turns orange then red, and pause beside the score.

## 6. Phase V: Reasons to Come Back and Sharing (Prompts 23–26)

### Prompt 23: Daily Run and Streaks

```
Add a Daily Run: Normal mode with a shard sequence seeded by the date, so every player gets the same run that day. Keep its own best score for the day and a streak for playing on consecutive days.
```

**Technical Implementation:**
- **Seed:** `shard_rng` is seeded from `_today()`, separate from the game's own `rng`.
- **Streak:** `streak` and `best_streak` in the save, using `_day_before()` to check yesterday.

### Prompt 24: Missions, Medals and Unlockables

```
Add 14 missions with progress counters, bronze, silver and gold medals at levels 5, 10 and 15 in each mode, and unlockable trails and echo colours earned through medals and missions. Show medals beside PLAY and the next medal during play, and put everything on a Progress screen and a Style screen.
```

**Technical Implementation:**
- **Missions:** `MISSIONS` (from FIRST STEPS to SHOW OFF), progress from `_mission_progress()`, a gold pop-up from `_mission()`.
- **Medals:** `MEDALS := [[5, "BRONZE"], [10, "SILVER"], [15, "GOLD"]]`, `next_medal()` for the hint beside the mode name.
- **Cosmetics:** `TRAILS` (Classic, Spark, Rainbow, Gold) and `PALETTES` (Neon, Sunset, Violet), unlocked by `_cos_open()`.

### Prompt 25: Crash-Safe Saves

```
Saving must never lose progress. Write to a temporary file first, keep the last good save as a backup, then swap. When loading, fall back to the backup if the main file is missing or broken.
```

**Technical Implementation:**
- **Write:** `_save()` writes `user://save.json.tmp`, renames the old save to `save.json.bak`, then moves the new file in.
- **Read:** `_load()` tries `save.json`, then `save.json.bak`.

### Prompt 26: Score Card and Sharing

```
Add a SHARE button on the results screen. Make a square score card with the logo, the mode or Daily badge, every one of your past runs drawn as neon trails, an X where you were caught, the score, the level, "ME VS N PAST SELVES" and "CAN YOU BEAT ME?". Open Android's share menu with the picture and a line of text.
```

**Technical Implementation:**
- **Card:** `_render_card()` draws `_draw_card_sq()` on a 360×360 `SubViewport` without the CRT and scales it to 1080×1080.
- **Android:** `_android_share()` adds the picture with `MediaStore` and opens an `ACTION_SEND` chooser through `JavaClassWrapper`, with a text-only fallback.
- **Text:** `_share_text()`, with room for `STORE_LINK` once there is one.

## 8. Phase VII: iPhone and iPad (Prompts 31–35)

### Prompt 31: Self-Install iOS Build

```
Make the game run on iPhone and iPad. It won't go on the App Store: people plug the device into a computer and install it with their own free Apple ID. Give Mac users a script that builds, signs and installs it, and give Windows users an IPA for Sideloadly.
```

**Technical Implementation:**
- **Export:** the iOS preset exports an Xcode project only (`export_project_only=true`), minimum iOS 14, with `NSLocalNetworkUsageDescription` for LAN games.
- **Mac:** `tools/ios/install-on-iphone.command` finds the Apple ID team, gives each person their own bundle id, and builds and installs with `xcodebuild` and `xcrun devicectl`.
- **Windows:** `tools/ios/make-ipa.command` builds an unsigned `ECHOES.ipa` for Sideloadly to sign.

### Prompt 32: Notches and 4:3 Screens

```
Keep the HUD clear of notches and rounded corners. On taller screens such as iPads, centre the whole interface instead of leaving an empty strip at the bottom, and keep the medal hint clear of the arena.
```

**Technical Implementation:**
- **Safe area:** `safe_l` and `safe_r` from `DisplayServer.get_display_safe_area()`, added to the HUD margins.
- **Centring:** `ui_oy` shifts every screen into a centred 216-pixel band; `_full()` keeps panels covering the whole screen and touch hit-tests use the same offset.

### Prompt 33: iOS Share Sheet

```
On iPhone and iPad, SHARE should open the real iOS share menu with the score card and the text, the same as on Android. If that isn't available, show the card sharp and readable, with short instructions that fit on the screen.
```

**Technical Implementation:**
- **Native part:** `tools/ios/native/EchoesShare.swift` presents a `UIActivityViewController` (as a popover on iPad); `tools/ios/add-native-share.sh` adds it to the exported Xcode project.
- **Handoff:** the game writes `share_request.txt` next to `echoes_score.png` in Documents; the native part picks it up and opens the sheet.
- **Photos:** `NSPhotoLibraryAddUsageDescription` added so *Save Image* works.
- **Fallback:** the card is resized with Lanczos to the exact size shown, so small text stays readable.

### Prompt 34: Touch Stick on Big Screens

```
On the iPad the stick feels slow. Make full speed come after the same thumb movement on every screen, about 7 mm, instead of a fixed number of game pixels.
```

**Technical Implementation:**
- **Radius:** `stick_r = clamp(7 mm × screen_get_dpi() × game pixels per screen pixel, 11, 22)`; phones stay at 22 game pixels and a 9.7-inch iPad drops to about 12.
- **Drawing:** the stick ring uses the same `stick_r`, so what you see matches how it moves.

### Prompt 35: Testing on Real Devices

```
Test on the real phone and tablet, not only on the computer. Take screenshots from the game on the device, run a bot game that presses SHARE, and put my saved progress back afterwards.
```

**Technical Implementation:**
- **Screenshots:** the Mac script launches the app with `--shot=user://NAME.png` and copies the file back with `xcrun devicectl device copy from`.
- **Share test:** `--autoplay --share_test --stay`; the app logs "ECHOES share: sheet shown" when the iOS sheet opens.
- **Progress:** `save.json` is copied off the device before a test and copied back after.

## 9. Compliance and Verification Summary

1. **Architecture:** Godot 4.7.2, GL Compatibility renderer, five GDScript files (about 2,550 lines), everything drawn in code at 384×216.
2. **Audio:** all music and sound effects generated by `tools/make_audio.py`; no outside samples.
3. **Platforms:** Android 7.0+ (arm64) and iPhone/iPad on iOS 14+; LAN play between any of them on the same Wi-Fi when everyone runs the same version.
4. **Testing:** headless bot runs (`--autoplay`, LAN `--host` / `--join` bots) and screenshot flags on Linux; checked on a Galaxy S25 and an iPad (6th generation).
5. **Release:** APK signed with the developer's own key (SHA-256 above), published on GitHub Releases with the iOS files; F-Droid recipe passes `fdroid lint`.
6. **Licensing:** Apache-2.0 for code, CC BY-SA 4.0 for art and audio.
